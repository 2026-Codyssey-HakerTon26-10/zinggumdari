## 2. 사람별

### 이초롱 · 백엔드1(판정)

1. DB 테이블과 `/profiles`, 시연 프리셋 페르소나(SPEC §2).
2. 규칙 엔진: 조건 상태, `any_of`, 만 나이 경계, `income_couple`, `opens_later`(SPEC §5).
3. `/judge`: 카드(우리가 읽은 조건 `read_as`, 근거 줄), 단계 넘기기, 조건에서 해둘 일·날짜 계산, 부모님 줄(SPEC §7, §8).
4. 손 조건표 부모님 5개(3절).
5. 그다음: 공고별 확인 질문(SPEC §6), 서류 사전 15종과 매핑 캐시.

다른 사람에게 주는 것: `judge(profile, rules)` 함수. 임종한의 검색 배지와 박범규의 가상 인구 전수 판정이 이것을 쓴다.

### 임종한 · 백엔드2(공고)

1. 손 조건표 시연용 3개(청년전용 버팀목, 신혼부부전용 전세자금, 신생아 특례 버팀목)와 그 원문 저장.
2. `to_lines()`: PDF, 웹 원문, API 산문 → 줄 목록(api.md §8). 시연 원문부터.
3. `/notices`와 원문 파일, `/ingest`(캐시 재생 토글 포함).
4. 공공데이터 덤프, 검색(2-gram BM25, 결과마다 배지).
5. 나머지 손 조건표 나 7개, 검수한 AI 조건표를 `reviewed`로 바꾸기.

손 조건표 담당이다. `resolve_manual`(원문 문장 → 근거 줄 ID)과 `verify`를 손 조건표에 돌리는 일, 개발·시험 분할(`eval/split.json`)도 맡는다.

다른 사람에게 주는 것: 줄 목록(임준현, 손보람), `rules/manual/`(이초롱, 박범규).

### 손보람 · 프론트

1. 시연 경로 화면을 영상 순서대로(SPEC §19.1): 시작(프리셋, 단계 넘기기 버튼) → 추천 카드 → 타임라인(표 보기 포함) → 검색 배지 → 원문 보기(근거 줄 하이라이트) → 공고 투입(검사별 ✓/✗, 캐시 재생) → 부모님 탭 → 서류 발급처.
2. 그다음: 가입·알림 설정 폼(SPEC §4), 공고별 확인 질문 한 줄, 알림함, 설정(삭제 1클릭).
3. 시연 영상 2분 녹화·편집.

API가 오기 전에는 api.md 예시 JSON을 목업으로 붙이고, 스텁이 오면 바꾼다. 디자인은 `UI플로우.html`, `컨셉보드.html`을 따른다.

### 임준현 · AI

1. LLM 호출 래퍼: Codyssey API(Anthropic 방식), 모델은 `LLM_MODEL`·`LLM_MODEL_BULK`, JSON 스키마 강제 출력(SPEC §9.2). 모델 확인은 끝났다(Background §5).
2. `compile()`, `verify()` 스텁 커밋(api.md 예시를 그대로 돌려준다).
3. 시연 투입 PDF 2건으로 자격 구간 → LLM 1회 → 검증기 → 빠짐 검사를 끝까지 돌리고 결과를 캐시한다.
4. 한국어 수·날짜 정규화와 검사마다 pytest.
5. 행안부 API 대량 추출(생애 단계 관련만), 프롬프트 동결(6절의 시각).
6. 발표자료 구성. AI 숫자는 박범규의 `eval/results.json`에서 옮긴다.

열지 않는 것: 시험용 손 조건표 10개, 페르소나 정답, 표본 채점표(3절).

다른 사람에게 주는 것: `compile()`(임종한의 `/ingest`), `rules/compiled/`(이초롱, 박범규), 투입 화면용 로그 예시(손보람).

### 박범규 · AI+인프라

1. 개발 환경: `.env` 키를 나누는 방법, CI 초록 유지, 백엔드 의존성, 외부 자원 표.
2. 페르소나 정답(3절).
3. 가상 인구 1만(시드 고정) → `judge()`로 전수 판정 → KNN과 정확도(무작위, 인기순과 비교).
4. 평가 채점: 시험용 10개의 자동 검증 정밀도, 빠짐, 판정 일치와 위험 오류 → `eval/results.json`, `/stats/coverage`. 대량 추출 표본 50개 채점.
5. 알림: 새 공고 재판정, 날짜 알림, 비슷한 가구 알림, SMTP 이메일, `/trigger/rebuild`, `/notify/test-email`.
6. 제출: 내부 마감 커밋 해시, `팀명_소스코드.txt`, 외부 자원 "(채울 것)" 0개. V100은 쓰면 용도를, 안 쓰면 "미사용"을 적는다.

## 3. 손 조건표와 정답

AI 공고 읽기를 짜는 사람(임준현)과 정답을 만드는 사람을 나눈다(SPEC §17).

| 무엇 | 누가 | 메모 |
|---|---|---|
| 손 조건표 나 10개 | 임종한 | 시연 3개 먼저 |
| 손 조건표 부모님 5개 | 이초롱 | 시연 2개(기초연금, 노인장기요양보험) 먼저 |
| 개발·시험 분할 `eval/split.json` | 임종한 | 시연 5개는 화면에서 누구나 보게 되므로 개발용, 나머지 10개는 시험용 |
| 페르소나 정답 `eval/personas/` | 박범규 | 함정: 혼인 8년차, 소득 초과, 64세, 접수 끝난 청년월세, 만 나이 경계 |
| 대량 추출 표본 50개 채점 `eval/sample50.json` | 박범규 | 대량 추출이 끝나면 |
| AI 조건표 검수(`reviewed`) | 임종한 | 시연 카드에 올릴 2개 먼저 |

- 임준현은 시험용 손 조건표, 페르소나 정답, 표본 채점표를 열지 않는다. 프롬프트와 신호어 목록은 개발용 5개로만 맞춘다.
- 시험용 채점은 프롬프트를 동결한 뒤 한 번 돌린다.
- 페르소나 정답은 만든 사람(박범규)만 연다.
