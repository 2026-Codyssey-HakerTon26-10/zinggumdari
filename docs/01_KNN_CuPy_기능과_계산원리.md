# 징검 KNN의 의도한 기능과 CuPy 거리 계산 원리

작성 기준일: 2026-11-01 (한국시간)

## 1. 목적과 결론

징검의 KNN은 사용자와 비슷한 특성을 가진 비교 인구를 찾아, 추가 확인할 복지·주거 정책 후보를 구성하는 데 사용하는 검색 모듈이다. CuPy는 이때 필요한 배열 연산을 NVIDIA L4 GPU에서 실행하는 Python 라이브러리다. 별도 추천 모델이나 독립 실행 보조 서버는 아니다.

현재 GPU 서비스는 ‘입력 벡터 → 유사한 행의 식별자와 거리’까지 담당한다. 최종 정책 추천에는 이웃별 정책 해당 여부, 사용자 본인의 규칙 판정, 지역·기간 필터가 추가로 필요하다. 유사성은 수급 자격이나 금융상품 적격을 확정하는 근거가 아니다.

이 문서는 로컬 구현 코드와 사용자가 제공한 서버 실행 결과에 근거한다. 실제 서버의 현재 파일을 다시 내려받아 대조한 감사 결과는 아니다.

## 2. 의도한 서비스 흐름

```text
사용자의 추천 요청
  → 운영 백엔드가 로그인한 본인의 프로필 조회
  → 비교 데이터와 같은 기준으로 32차원 벡터 변환
  → 인증된 GPU KNN 요청
  → 가까운 비교 행 ID·거리 반환
  → 이웃별 정책 해당 여부 집계
  → 본인 조건·지역·마감일 확인
  → 추가 확인이 필요한 정책과 근거를 화면에 표시
```

Render PostgreSQL에 가입 정보가 저장되어 있어도 이 설계는 가능하다. DB 전체를 GPU로 복사하는 것이 아니라, 추천 요청에 필요한 프로필을 읽어 변환한 검색 벡터만 보내는 방식이다. 이메일·비밀번호·로그인 세션은 거리 계산에 필요하지 않다.

현재 GPU가 비교하는 인구와 Render에 가입한 실사용자는 서로 다른 데이터 집합이다. 회원가입을 했다고 비교 행렬에 자동 추가되는 구현은 확인되지 않았다.

## 3. 비교 데이터와 전처리

배포용 파일은 `X.npy`, `users.parquet`, `meta.json`이다. 메타데이터에는 전체 10,000행, holdout 1,000행이 기록되어 있다. GPU 로더는 `split=pool`인 9,000행만 검색 대상으로 올린다. holdout을 제외하는 것은 평가 데이터의 검색 풀 혼입을 막는 조치이며, 이것만으로 독립 성능 평가가 완료되는 것은 아니다.

메타데이터는 데이터 기반을 ‘가상 인구(가정 분포)’로 명시한다. 출처는 NVIDIA Nemotron-Personas-Korea로 기록되어 있고, 일부 항목은 텍스트에서 추출하거나 가정값으로 생성했다. 실사용자의 실제 정책 이용 이력이 아니다. 출처의 라이선스·가공 적합성에 대한 별도 감사는 이번 문서 범위에 포함하지 않았다.

### 입력 32개 열의 구성

| 분류 | 열 수 | 내용 |
|---|---:|---|
| 연령·성별 | 2 | 정규화 연령, 여성 표시 |
| 지역 | 3 | 서울·경기·기타 |
| 혼인 | 5 | 미혼·예비부부·신혼·기혼·이혼/사별 |
| 자녀·가구 | 3 | 자녀 수, 6세 이하 자녀 여부, 가구원 수 |
| 취업 | 6 | 재학·구직·재직·자영업·육아휴직·기타 |
| 임신 | 1 | 임신 여부 |
| 주거 점유 | 5 | 자가·전세·월세·보증부월세·무상거주 |
| 기타 | 7 | 세대주·무주택·맞벌이·가구소득·부양가족 수·노부모 부양·청약통장 |

`features.py`에는 `stage2()`와 `query_vector()`가 존재한다. 수치 5개는 비교 인구에서 정한 최소·최대값으로 정규화하고 0~1 범위로 제한한다. 범주형 값은 원핫 또는 이진 값으로 바꾸며, 미입력은 NaN으로 유지한다. 요청 JSON에서는 미입력을 `null`로 전달한다.

일반적인 수치 변환식은 `정규화 값 = (원래 값 − 최소값) / (최대값 − 최소값)`이다. 신규 사용자마다 최소·최대를 다시 계산하면 안 된다. 비교 인구의 scale과 열 순서를 그대로 사용해야 한다.

현재 `query_vector()`는 `birth_year`를 사용해 `year − birth_year`로 연령을 만든다. 반면 첨부 DB 스키마에는 `birth_date`가 있다. 두 필드의 변환과 기준일 계약은 별도로 연결해야 한다. 이 계산은 생일 경과를 반영한 만 나이와 다르므로 정책의 연령 자격 판정에 그대로 사용해서는 안 된다.

## 4. 실제 거리 계산식

사용자 벡터를 q, 비교 인구 i번째 행을 xᵢ라고 하자. 두 값이 모두 유한한 열의 집합을 Jᵢ라 하면 현재 코드는 다음을 계산한다.

```text
dᵢ = √[ Σ(j∈Jᵢ) (xᵢⱼ − qⱼ)² / |Jᵢ| ]
```

이는 공통으로 알려진 차원에 대한 제곱 차이의 평균을 구한 뒤 제곱근을 취하는 RMS 거리다. 일반적인 유클리드 거리에서 비교 차원 수로 보정한 형태이며, 공통으로 알려진 항목이 하나도 없으면 무한대 거리로 처리해 결과에서 제외한다.

예를 들어 설명용 3차원 입력이 `[0.4, 1, 미입력]`, 비교 행이 `[0.6, 1, 0.2]`이면 마지막 항목은 제외한다. 거리는 `√((0.2² + 0²)/2) ≈ 0.1414`다. 이 숫자는 원리 설명용이며 실제 평가 성능이나 사용자 결과가 아니다.

## 5. CuPy가 GPU에서 하는 일

CuPy는 NumPy와 유사한 배열 인터페이스를 제공하되, GPU 메모리의 배열을 대상으로 연산한다. `cp.asarray()`는 CPU 쪽 데이터를 GPU 배열로 옮기고, `cp.asnumpy()`는 계산 결과를 CPU로 가져오는 데 사용된다. [CuPy 공식 기본 사용법](https://docs.cupy.dev/en/stable/user_guide/basic.html)

현재 구현의 순서는 다음과 같다.

1. 서비스 시작 시 pool 행렬을 float64 형식으로 GPU 메모리에 올린다.
2. 요청 벡터를 GPU 배열로 변환한다.
3. 모든 행에 대해 유효값 마스크, 차이, 제곱, 행별 합, 개수 보정, 제곱근을 계산한다.
4. 거리 배열을 CPU로 가져온다.
5. CPU의 NumPy가 k번째 거리 경계를 구하고, 이웃 선택·안정 정렬·JSON 구성을 수행한다.

따라서 현재 구조는 ‘거리 계산은 GPU, 최종 이웃 선택은 CPU’이다. 모든 계산이 GPU에서 수행된다고 표현하면 부정확하다. 모든 후보를 직접 비교하는 방식이며 별도 근사 최근접 검색 인덱스나 신경망 학습 단계는 없다.

9,000×32×8바이트인 원본 float64 행렬은 약 2.30MB다. 실제 GPU 메모리는 CUDA 컨텍스트·임시 배열·메모리 풀 때문에 더 사용된다. 서버 출력에서는 202MiB가 관측됐으나 이 값을 행렬 자체 크기로 해석해서는 안 된다.

## 6. k, 동점, 반환값

API는 k를 1~100으로 제한하며 기본값은 50이다. 다만 k번째 거리와 같은 후보를 모두 포함하므로 실제 결과 수는 k를 초과할 수 있다. 이전 설명의 ‘최대 k개 반환’은 현재 코드와 맞지 않아 본 문서에서 정정한다. 특히 입력이 적거나 동일 벡터가 많으면 동점이 많아질 수 있다.

동일 거리에서는 원래 pool 행 순서를 유지한다. 응답에는 데이터 버전, `backend=cupy`, 요청 k, 실제 count, 각 이웃의 `user_id`, `source_row`, `distance`가 들어간다. 반환되는 user_id는 비교 인구 식별자이며 Render 실사용자 계정 ID라고 가정하면 안 된다.

`/metadata`는 열·scale·기준일·버전을 제공한다. `/neighbors`는 32개 입력, 버전 일치, 인증을 검사한다. 버전 불일치는 409, 잘못된 입력은 422, 미준비나 큐 포화는 503으로 처리한다. 버전은 세 데이터 파일의 해시에서 만들어지며 변환 코드 버전 자체까지 보증하지는 않는다.

## 7. 검색 이후 정책 후보를 만드는 원리

로컬 `knn.py`에는 CPU `recommend()` 함수가 존재한다. 이 함수는 인구 행×정책 열 형태의 불리언 해당 여부 행렬과 개인별 규칙 판정 결과를 외부에서 받아 사용한다.

현재 코드의 후보 조건은 본인 대상 정책, 개인 판정 `needs_check`, 지역 일치, 기한 미경과, 이웃 해당 비율 0.3 이상이다. 정책 유형당 최대 2개, 전체 최대 5개를 선택한다. 입력 필드가 적거나 대표 집단 비중이 낮으면 참고 수준으로 표시한다. 이 함수 내부는 CPU `neighbors()`를 호출하므로 GPU 결과를 추천 함수에 사용하는 운영 연결은 별도 작업이다.

이웃 해당 비율은 가상 인구에서 조건에 해당하는 비중이다. 실제 신청 인기, 수급 확률, 정책 효과, 추천 정확도가 아니다. 관련 행렬과 규칙 판정이 준비되지 않으면 이웃 ID만으로 유효한 정책 후보를 완성할 수 없다.

## 8. 기술적 한계와 해석

- GPU 계산의 장점은 대규모 반복 배열 연산이지만, 현재 크기에서 CPU보다 빠른지는 측정되지 않았다. 통신·직렬화·GPU 전송 비용을 포함한 비교가 필요하다.
- 미입력 차원을 제외하므로 적은 정보만 공유하는 행도 낮은 거리를 받을 수 있다. 공통 정보량과 결과 해석을 함께 다뤄야 한다.
- 원핫 열 수가 많은 범주는 거리 기여도가 달라질 수 있다. 현재 식은 변환된 열을 동일하게 취급하며 의미별 가중치를 자동 학습하지 않는다.
- 정규화 범위 밖의 값은 잘린다. 메타데이터의 출처 연령 범위는 19~39세로 기록되어 있어 중장년 대상까지 대표한다고 주장할 수 없다.
- 서울·경기 외 지역은 하나로 묶인다. 세부 지역 자격은 후속 규칙 판정에서 확인해야 한다.
- 동점 포함, 실사용자 필드 매핑, 정책 해당 표의 행 순서와 버전은 서비스 연결 시 핵심 계약이다.
